**Goal:** Wire the missing owner control-panel UI (claim, white-label, visibility) to SPEC 04's already-shipped,
already-gated routes, fold in the post-merge smoke fixes (result copy + two render bugs), and light up the four
dead analytics events — pure front-end wiring, no migrations, no new backend except one read-only ownership probe.

**Architecture:** The `/r/[slug]` page is ISR (`revalidate = 300`) and session-unaware. All owner controls are a
**client island** that hydrates, calls a read-only `GET /api/reports/[slug]/mine`, and renders controls for the owner
only. The cached public HTML stays byte-identical for everyone. All writes go to the four existing gated routes
(unchanged). The dashboard reuses the same client controls, fed by a session-aware server loader.

**Tech Stack:** Next.js 15 App Router (typed routes), React client components, Supabase (server + admin clients),
vitest + RTL, PostHog `track()`.

## Global Constraints (copied verbatim from the specs / repo law)

- **ISR integrity (§0, load-bearing):** `/r/[slug]/page.tsx` stays `export const revalidate = 300`. No session data
  in the cached HTML. Owner UI is a client island only. `page.tsx` must not read `cookies()`/`auth`.
- **Client cannot widen a server gate (§8):** UI locked/enabled state is cosmetic. The four routes
  (`claim`/`visibility`/`white-label`/`logo`) are **not modified** — auth→paid→verified-owner→claimed is enforced there.
- **No migration, no env var, no bucket change, no flag, no gating change, no contract/snapshot change.** `packages/types`
  is **untouched** (dashboard report-settings + probe response use apps/web-local types).
- **Only new backend = the read-only `GET .../mine` probe** (no-store, deny-by-default, `{owned:false}` for anon).
- **SPEC 04 §12 non-regression holds** (SSRF, RLS, grade weights, snapshot immutability, JS/SPA detector, Turnstile/rate
  limits, `PASSING_SCORE=60`, cure gating, share text engine-data-only).
- **XSS:** brand name + all crawled strings are plain React text (escaped). Decoded URLs are plain text, never
  `dangerouslySetInnerHTML`. Logo stays server magic-byte-validated (no SVG) — client checks are UX-only.
- **§6 DISPLAY-ONLY:** decode URLs only at human-facing display sites. Stored snapshot values, `href`s, `?ref=`, and the
  action-packet machine/pasteable payload (`actionPacket.body`, clipboard) are unchanged.
- **Route-segment exports are static literals.** `nvm use 22`. No tooling/vendor names or automated-authorship
  trailers in commits/PRs/code. Small conventional commits. Show full diff + STOP before push. PR only; no merge without owner go.

## Owner rulings (approved 2026-07-08 — binding)

**R1 — Verify→claim return path (BOTH mechanisms).** Primary: re-probe on return to `/r/`. AND: thread the report path as
`?next=` into the verify flow and render a **"Return to your report"** link on `VerifyClient`'s verified card (without it
a user bounced into domain-verification mid-claim dead-ends — the top Pro-conversion flow). **`?next=` is
attacker-reachable → validate as a same-origin RELATIVE path only** via a new `lib/safe-next-path.ts` (`safeNextPath(next):
string | null` — reject `//host`, `https://…`, `/\`, backslash / scheme / encoded off-origin; accept only a
single-leading-slash relative path). The verify **page server component** validates before passing `returnTo` to
`VerifyClient`; `ClaimControl` constructs `?next=/r/<slug>`. **A test pins that an absolute/off-origin `?next=` is rejected
(no link rendered → no open redirect).**

**R2 — Probe is the single source of truth; refetch after EVERY write.** The `.../mine` probe response is the ONLY thing
the client trusts for control visibility/state. `ReportOwnerIsland` owns the `probe` state + a `refetch()` and passes it
to **all** controls; **claim, white-label, AND visibility** each call `refetch()` on a 200 write — never only claim — so
control state is never stale after acting. Controls derive `listed/indexable/whiteLabel/canWhiteLabel/claimed/owned` from
the probe (only transient input such as the brand-name field is local). White-label save additionally calls
`router.refresh()` (the route purged the ISR tag) so the server-rendered brand header updates. **Tests pin that
`fetchOwnership` is re-invoked after each of the three write paths.**
