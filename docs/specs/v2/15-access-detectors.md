# 15 — Crawler-access detectors

> Generated by `packages/engine/src/v2/access/spec.ts`; do not edit by hand. Regenerate with
> `pnpm --filter @crawlmouse/engine exec tsx src/v2/access/write-spec.ts`.

`detectAccess` is a pure function of one check (`AccessInput`): the rows of its access batches and the
crawled pages' robots.txt readings for the search engines (`robots_search`). It returns the crawler matrix, whether the access score is withheld, and one
record per crawler for each access fix type, sorted by fix type and then key. CC-17 turns a record into the
diff's outcome. The tests that pin each rule below:
`pnpm --filter @crawlmouse/engine exec vitest run src/v2/access`.

## What the worker decides, and where the engine takes over

The crawl worker (CC-12, `packages/worker/src/verdict/table.ts`, spec 12) decides each crawler's verdict
and cause on each sampled page, and the engine does not decide them again. In the worker's table a robots.txt
disallow is decided before any request, and a refusal, a block or a challenge only after the untagged browser
control was served on that page; a refusal is `blocked_by_ua_rule` only when the tagged Googlebot canary was
served on the same page. The engine reads each crawler row as the worker wrote it and decides what the rows
add up to.

## Inputs

`cells.ts` reads the input: from each worker row (`AccessTest`) with a crawler `ua`, its
`id`, `ua`, `page_url`, `template_key`, `verdict`, `cause`, `raw_status` (as the cell's `status`),
`evidence_class` and `headers`; from each crawled page its `url`, `template_key` and `robots_search`. URLs
robots.txt kept our crawler from are not read, so every crawler is judged on pages our crawler fetched and one
wildcard rule reads the same for each. The control's and the canary's rows (`ua` null) are not read.

Refused as input: a row for a token the registry does not mark testable; two rows for one crawler on one page;
a sampled page without a row for a testable crawler; a page listed twice; a robots.txt reading for a token that
is not a search engine in the registry; a registry entry that is neither testable nor a search engine; and a
row whose cause or evidence class the worker's table never gives its verdict:

## The matrix

A crawler's cells are its worker rows, one per sampled page, or, for a search engine, robots.txt's reading for
it on each crawled page. Its site verdict:

1. No measured cell (not `not_measured`, `edge_blocks_automation`): `edge_blocks_automation` when a
   cell carries it, otherwise `not_measured`.
2. Otherwise the verdict most measured cells carry. A tie goes to the earlier in this order, the weaker claim
   first: `allowed_thin`, `allowed`, `rate_limited`, `redirected_away`, `payment_required`, `refused_unverified`, `challenged_ua`, `disallowed_by_robots`, `blocked_by_ua_rule`.
3. A block (`disallowed_by_robots`, `blocked_by_ua_rule`) is never the site verdict when a page served the crawler
   (`allowed`, `allowed_thin`): then it is rule 2 over the served cells.
4. Nor unless the blocks together hold on at least half the measured pages and the block's own pages outnumber
   those whose real crawler may pass (`challenged_ua`, `refused_unverified`): then it is rule 2 over the measured pages that are
   not blocked.

The cells that carry the site verdict are its deciding cells.

| Field            | Meaning                                                                                                                                                    |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ua`             | The registry token.                                                                                                                                        |
| `group`          | The registry's group.                                                                                                                                      |
| `scored`         | The registry's `scored`.                                                                                                                                   |
| `verdict`        | The site verdict (below).                                                                                                                                  |
| `evidence_class` | `declared` when every deciding cell rests on robots.txt, otherwise `simulated`; with no cell, `declared` for a search engine.                              |
| `status`         | The status the crawler’s own request got on most deciding cells, the lower on a tie; a declared cell’s status is the robots.txt read’s and is not counted. |
| `pages_measured` | Cells with a measured verdict.                                                                                                                             |
| `cause`          | The cause the deciding cells name, when they all name the same one (none counts as one).                                                                   |
| `confidence`     | Below.                                                                                                                                                     |
| `by_template`    | The same rules applied to each template’s cells.                                                                                                           |
| `counts`         | Engine only: cells per verdict, measured or not, so the extent ("blocked on 18 of 20") is kept.                                                            |
| `supporting`     | Engine only: the deciding cells’ worker rows and pages.                                                                                                    |
| `intent`         | Engine only: `respected` when the site verdict is a robots.txt disallow.                                                                                   |

Confidence: `inconclusive` for an unmeasured verdict. `confirmed` only for a declared verdict that every cell
carries, robots.txt read the same on every page. Otherwise `likely`: a verdict that rests on our own requests
shows what the tagged request from our address got, not what the real crawler gets.

The access score is withheld when fewer than 2 scored crawlers have a measured site
verdict (`scoredCrawlersMeasured`, the contract's; FACTS I4). The contract counts `challenged_ua` and
`refused_unverified` as measured. `text_share` is not set here: it needs the rendered words (CC-14).

## Detectors

| Fix type                    | Key       | Subject                          | Detected                                                                                                                        | Not detected                                                                                                             | Indeterminate                                        | Measured                                                    | Affected                            | Class                    |
| --------------------------- | --------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- | ----------------------------------------------------------- | ----------------------------------- | ------------------------ |
| `edge_rule_blocks_crawler`  | `edge:`   | a crawler the worker requests as | `blocked_by_ua_rule` on 50 % or more of the pages judged, and on more pages than `challenged_ua`, `refused_unverified` together | served (`allowed`, `allowed_thin`) on 95 % or more of the pages judged                                                   | neither; or no page judged (the reasons below)       | the share of the pages judged that are `blocked_by_ua_rule` | the blocked pages, when detected    | `confirmed_defect`       |
| `robots_txt_blocks_crawler` | `robots:` | any registry crawler             | robots.txt disallows it on each page its rules were read for: intent `respected`                                                | robots.txt allows it on one or more of those pages (a partial disallow, such as one path, is not a block of the crawler) | no page's rules were read for it (`robots_not_read`) | the share of those pages robots.txt disallows it on         | the disallowed pages, when detected | `documented_requirement` |

**Edge.** The pages judged are those where the crawler's own request got an answer: `allowed`, `allowed_thin`, `blocked_by_ua_rule`, `challenged_ua`, `refused_unverified`, `rate_limited`, `payment_required`, `redirected_away`.
Only `blocked_by_ua_rule` counts as blocked. A record names the edge, never robots.txt: a page robots.txt
disallows is not one the edge was tested on, and robots.txt as the cause of any other verdict is refused as
input. A detected record's evidence is the blocked rows; another record's is the rows that were not served.
Confidence: `likely` when decided, since the evidence is our own requests; `inconclusive` when indeterminate.

**Robots.** A robots.txt disallow is the site's stated intent: until the site can state its own policy per
crawler, each one is `respected`. The record is detected, the fact the screen states, with `opens_fix` false;
how a respected-intent record weighs in the grade is CC-17's to apply. For a worker row,
`disallowed_by_robots` is the reading, and any other verdict but `not_measured` was decided after robots.txt
allowed the crawler on the page, since the worker decides a disallow first; a `not_measured` row may come before
robots.txt was read, so it counts neither way. Confidence: `confirmed` when decided with every page's rules
read, `likely` when decided with some not read, `inconclusive` when indeterminate.

### Indeterminate reasons

| Reason                            | Meaning                                                                                                                                                                                                              |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `not_measured`                    | edge: no page where the crawler’s own request got an answer, and none of the two below                                                                                                                               |
| `edge_blocks_automation`          | edge: the edge refused or challenged the untagged browser control too, so it treats all automation that way; the crawler was not requested                                                                           |
| `robots_disallows`                | edge: no page where the crawler’s own request got an answer, and robots.txt disallows it on one or more pages, so the edge was not tested there                                                                      |
| `challenge_real_crawler_may_pass` | edge: neither threshold met, and challenges are the commonest answer that was not a serve, at least as common as the blocks: the real crawler, from its own addresses, may pass a challenge                          |
| `refusal_unverified`              | edge: neither threshold met, and unverified refusals are the commonest such answer, at least as common as the blocks: the tagged Googlebot canary was not served on those pages, so IP verification is not ruled out |
| `edge_answered_otherwise`         | edge: neither threshold met, and `rate_limited`, `payment_required`, `redirected_away` are the commonest such answer, at least as common as the blocks                                                               |
| `hysteresis_band`                 | edge: neither threshold met, and the blocks are more common than each of the answers above                                                                                                                           |
| `robots_not_read`                 | robots: no page's robots.txt rules were read for the crawler                                                                                                                                                         |

What the diff does with an indeterminate record, by the fix's status before the check
(`LIFECYCLE.indeterminate`):

| Fix before          | Action             |
| ------------------- | ------------------ |
| `none`              | `untouched`        |
| `open`              | `remeasure`        |
| `marked_done`       | `unable_to_verify` |
| `verified_resolved` | `remeasure`        |
| `unable_to_verify`  | `untouched`        |
| `reopened`          | `remeasure`        |

| Field                  | Meaning                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| `type`                 | The fix type.                                                                                               |

| `key`                  | The prefix, a colon, and the crawler’s token in lower case.                                                 |

| `group`                | The registry's group.                                                                                       |

## Signals

Only the signals marked below count toward the AI readability grade. The others carry no weight, and no fix
type exists for them (`FixTypeSchema`), so none can be reported as a defect.

| Signal                 | Counts toward grade | Recommendation class |
| ---------------------- | ------------------- | -------------------- |
| `schema_org`           | yes                 | `best_practice`      |
| `content_signals`      | yes                 | `best_practice`      |
| `web_bot_auth`         | no                  | `experimental`       |
| `llms_txt`             | no                  | `experimental`       |
| `mcp_server_card`      | no                  | `experimental`       |
| `markdown_negotiation` | no                  | `experimental`       |
| `agent_skills_index`   | no                  | `experimental`       |

`declarationSignal` judges what one GET of a declaration's path answered: 200 with a body of an expected media
type is `detected`; 404 or 410, an empty body or an HTML page is `not_detected`; another media type, no
answer, no request or another status is `indeterminate`. The worker does not request these paths yet.

| Signal            | Path               | Media types                   |
| ----------------- | ------------------ | ----------------------------- |
| `llms_txt`        | `/llms.txt`        | `text/plain`, `text/markdown` |
| `mcp_server_card` | `/.well-known/mcp` | `application/json`            |
