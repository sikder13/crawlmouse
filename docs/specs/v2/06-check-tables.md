## How access works

- RLS is on for each table 003 creates, and each starts with `revoke all … from public, anon, authenticated`: production's default privileges would otherwise give `anon` every privilege on a new table, TRUNCATE included. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-check-tables.test.ts -t "posture"`.
- `authenticated` reads site data through `is_member_for_site(site_id)`, directly or through the row's check, and account data (`api_keys`, `seat_sites`) through `is_member()` / `member_role()`. SELECT is granted per column. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-cross-account.test.ts`.
- **Client scope.** `is_member_for_site` is true when the caller has an active seat on the site's live (not soft-deleted) account and that seat covers the site. A seat covers a site when `seats.client_scope_all` is true (the contract's `client_scope: 'all'`; the default, so the seats 001 created keep full access) or when `seat_sites` pairs the seat with the site or with the production site it stages. An owner seat cannot be scoped (`seats_owner_unscoped`).
- `site_fixes` (the packet is Pro content), `fix_events` and `share_links` have no client grant: reading `site_fixes.packet` as `authenticated` is a permission error, not an empty result. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-cross-account.test.ts -t "packet"`.
- `alert_rules` is the one client-written table: a site rule by the seats that cover the site, an account-wide rule by the owner. The trigger `alert_rules_entitlement_check` refuses a write that adds Slack while the account's effective tier is Free; it runs after the row's RLS check and for the service role too. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-check-tables.test.ts -t "alert_rules"`.
- `measurement_lineages` is readable by every signed-in user: it names Crawlmouse's own builds, nothing of an account's. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-cross-account.test.ts -t "measurement_lineages"`.
- A partition is reached only through its parent: partitions live in the schema `partitions`, which no client role may use, with RLS on and every role's privileges revoked. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-006b-data-foundations.test.ts -t "monthly partitions"`.
- An anonymous site (`account_id is null`) is not readable through RLS (`is_member_for_site` joins the site's account); `/audit/[id]` reads it with the service role, as v1 does. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-cross-account.test.ts -t "anonymous sites"`.

## The `crawl_worker` token

The Fly worker is meant to reach Supabase with this token and nothing else. It never holds the project's JWT signing key: whoever holds a signing key can mint a `service_role` token too.

- **Who mints it.** The server, in the Inngest step that posts a batch to the worker, one token per check (or per batch). It is signed with a project JWT signing key the server holds: the legacy JWT secret, or a key imported into the project's JWT signing keys (Supabase supports importing a private key or setting a shared secret for this). That key is server-side, at the same tier as the service-role key.
- **Claims.** `role: "crawl_worker"`, `check_id` (a lowercase uuid), `lineage_id` (the lowercase uuid of the `measurement_lineages` row the server registered for the batch), `iat` and `exp` as numbers, `exp − iat` at most 900 seconds. No `sub`: the token is not a user.
- **What the database checks.** `crawl_worker_check_id()` reads the verified claims (`auth.jwt()`) and returns the check only when the role claim is `crawl_worker`, `check_id` is a well-formed uuid naming a check in status `running`, `exp` has not passed, `iat` is at most 60 seconds ahead of the database clock, and the lifetime is at most 900 seconds. Both policies hold only for that check, so a token minted with a longer life, for another check, or for a finished one is refused by the database, not only by the minter. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-007-storage.test.ts`.
- **Lineage and month.** A `page_results` row must name the token's `lineage_id`. A row that leaves out `check_month` or `lineage_id` takes them from the token (column defaults that call `crawl_worker_check_month()` and `crawl_worker_lineage_id()`), so the worker's row needs no partition key of its own. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-007-storage.test.ts -t "from the token"`.
- **What it may do.** Insert `page_results` rows for its check, without RETURNING (`Prefer: return=minimal`), and upload `evidence` parts under `{account_id | anon}/{site_id}/{check_id}.part{n}.json.gz`. It cannot read, update or delete either, and holds no grant on `frontier` until `frontier.audit_id` stops being NOT NULL. A leaked token can still write any number of rows and parts for its check within its 15 minutes; nothing in the database caps volume.
- **For the step that wires the worker.** Whether the server can mint today depends on the project's key setup, which this step does not read. If the project signs only with Supabase-managed asymmetric keys, the server has no private key to sign with, and a key must be imported (or a shared secret set) before the worker can run. That is a blocker for the wiring step, not for these migrations.

## Where this differs from the design documents

The merged contract (`packages/types/src/v2`) wins where it and ARCH-2 disagree; the owner's rulings of 2026-11-02 settle the rest. The contract guard compares the columns and value sets with the contract: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-contract-guard.test.ts`.

- **Columns and enums follow the contract.** `checks.status` is the contract's `CheckStatus` (ARCH-2 has `canceled` and `refused`, the contract has `partial`); `checks.trigger` is `CheckTrigger` (`first_audit`, `fix_recheck`); `grade_version` is a semver string, not a smallint; `sites.host`, not `hostname`; a staging site points at its production site through `staging_of_site_id` (ARCH-2: `kind` and `parent_site_id`), and competitors are `sites.competitor_hosts`, not rows. Fix types and statuses, change kinds and subjects, alert-rule kinds and fields, report kinds and formats, and `page_results.kind` (v1's `PageKind`) are the contract's lists. `link_edges.js_only` replaces ARCH-2's `via`. The contract's `Fix` is the table `site_fixes`, as ARCH-2 §2.1 (not §2.8's `fixes`).
- **Where the contract's objects are stored.** `Site.schedule` is the `schedule_*` columns (weekday ISO 1–7; ARCH-2's `schedule_dow` is 0–6); `Site.client_report` is `report_schedules`, one row per site keyed by `site_id` (ARCH-2: an `id` key, `recipients`, `send_hour`, `reply_to`, `kind`, `enabled` and a `monthly_first_monday` cadence); `Seat.client_scope` is `seats.client_scope_all` with `seat_sites` (created here, not in 001, because it references `sites`); `Site.paused` is generated from `paused_reason`.
- **Access rules ship with the tables (003), not in a later 006.** A table without them would be open to `anon` from the moment it exists.
- **Per-seat client scoping is in the database** (`is_member_for_site`), not only in route handlers: a signed-in user can call PostgREST directly.
- **No client write on `sites`.** ARCH-2 §2.2 rule 3 grants a client update on the schedule columns behind an entitlement trigger; the brief keeps `alert_rules` the only client-written table, so schedule changes go through a route.
- **`checks` has no `account_id`.** ARCH-2 copies it for RLS speed; here a check reaches its account through `sites`, so no copy can drift from the site's. Its listing index is `(site_id, queued_at desc)` (ARCH-2: `finished_at`), because a queued or running check has no `finished_at`. ARCH-2 says a check is immutable once finished; nothing enforces it here (the contract clears `expires_at` when an account keeps a finished check).
- **`page_results` and `link_edges` are keyed by URL hashes** (sha256 of the UTF-8 URL, as `frontier.url_hash`), set by a trigger: the contract identifies them by URL, and a URL can exceed a btree key. Their keys, and `access_tests`', also hold `check_month`, because a partitioned table's unique keys must include its partition key; a writer's `on conflict` target names it too.
- **The `changes` idempotency index** is `(check_id, kind, subject, "where", ua, fix_id)` with `nulls not distinct`. ARCH-2's `(check_id, kind, subject)` assumed a fine-grained subject (`crawler:claude-searchbot`); the contract's is a category (`ChangeSubject`). The owner approved the key without `fix_id`; review showed two fixes opened in one check can share subject, place and crawler, so `fix_id` is part of it (owner ruling 4: confirmed).
- **`alert_events`** is unique on `(rule_id, check_id, channel)`: one rule sends on each of its channels. ARCH-2 says `(rule_id, check_id)`.
- **`alert_rules_entitlement_check`** (ARCH-2's name) refuses only a write that adds Slack, and runs after RLS. A rule that already sends to Slack stays updatable after a downgrade, so the owner can switch it off and alertFn can stamp `last_fired_*`; alertFn decides at send time whether the plan still includes Slack.
- **References between check rows are checked.** Composite foreign keys keep a report, rule, schedule, seat pairing and owner seat inside one account, and a check, change, fix or alert event inside one site. Triggers check what a foreign key cannot: a fix event's check and seat (`fix_events_references`), a rule's last-fired check (`alert_rules_fired_check_scope`) and an alert event's rule (`alert_events_rule_scope`). `fix_events.check_id` is deferred, so deleting an account or a site takes its fixes' events in the same statement as its checks; deleting a check an event still cites fails at commit. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-check-tables.test.ts -t "deleting"`. The triggers check a row when it is written; a later service-role change to a parent's site or account (a rule's `site_id`, a fix's `site_id`) is not re-checked against rows that already cite it. No client can make such a change: neither column is in a client grant.
- **`share_links`** stores the token's sha256, not the token. **`fix_events`** has no client grant, like `site_fixes`.
- **Pausing keeps the schedule.** A paused site keeps its cadence, weekday and hour and records `paused_reason`; CC-02's planner models the same pause as `schedule = null`. A site checked on deploy keeps that cadence, except that on a move to Free the oldest site, unless the user paused it, takes Free's monthly check, because Free has no deploy hooks (`GATES.free.stagingAndDeployHooks`; owner ruling 2: confirmed). A site given a timed cadence without a weekday or hour gets its creation weekday, in the account's time zone (UTC when Postgres does not know the zone), at 06:00 (ARCH-2's defaults). A staging site follows the new tier's gates on every transition (owner ruling 3, `planStagingSites`): on a tier without staging (Free) a running staging site pauses as `staging_not_in_plan`, keeping its schedule, and on a tier with staging it runs again; a staging site paused for another reason is not changed. `sites_staging_pause` allows that reason on staging sites only. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-site-effects.test.ts -t "staging"`.
- **Counts** are `integer` columns, `bigint` for byte counts: the contract's counts are unbounded safe integers, and `integer` caps them at 2,147,483,647. **Text** columns refuse a NUL character, which the contract's strings accept, and so does jsonb inside a string (`page_results`' `hreflang`, `canonical_declared.href` and `robots_search[].ua` among them); the engine strips NUL before persisting. **Dates** have no year 0 in Postgres; the contract's `YYYY-MM-DD` accepts `0000`, so a writer must not pass one (follow-up below).
- **`reports.site_id` is required** (the contract); ARCH-2 allows null for an agency-wide export. ARCH-2's `reports.check_id`, `brand_id` and `schedule_id` are not built.
- **`api_keys.scopes`** are ARCH-2's `read:checks`, `read:fixes`, `read:changes`; SECURITY-DESIGN §3.6 says `['read']`.
- **The evidence path** is ARCH-2 §2.10's `{account_id | anon}/{site_id}/{check_id}…`; SECURITY-DESIGN §7.1 shows `account/<id>/site/<id>/check/<id>`.
- **Not built here:** ARCH-2's `sites.root_url`, `etld1`, `verified_at`, `verification_method`, `public_slug`, `schedule_offset_min`, `next_check_at`, `page_cap`, `latest_check_id` / `previous_check_id`, `trial_protected_until`; the `checks` pipeline columns and the J7 token hash. The contract does not name them, and a column added later is hidden from clients until it is granted. ARCH-2 §2.15's tables (`crawl_batches`, `recipient_confirmations` for J10's double opt-in, `integrations` and the rest) are their own steps, as are SECURITY-DESIGN §10 #8's share and portal RPCs and #12's redaction of stored request headers (the writer's job).

## Follow-ups

- **Ruled for 004:** v1 audits with status `canceled` have no v2 status; the backfill rules on them.
- **The deploy-hook receiver and the route that unpauses a site check the plan.** A Free account can hold a site whose cadence is `on_deploy` (owner ruling 2), so the receiver checks `GATES[tier].stagingAndDeployHooks` before it starts a check, and unpausing a site on a tier without deploy hooks gives it that tier's cadence.
- **alertFn checks Slack at send time.** A rule that already sends to Slack stays enabled-able after a downgrade (the trigger refuses only adding Slack), so the step that builds alertFn checks the account's effective tier before each Slack send.
- **The writer validates.** The rules and enums listed above as not checked by the database are the writer's: CC-20's insert path parses each row with the contract schema before it writes.
- **The contract does not name** the database-only columns in the table below.
- **A `sitemap_lastmod` in year 0** passes the contract and is refused by the `date` type, so the step that writes it from a crawled sitemap drops or refuses such a date. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-rule-agreement.test.ts -t "year 0"`.
- **No 2,048-character URL cap.** The worker cuts URLs to 2,048 characters (`packages/worker/src/rows/bounded.ts`), but the contract's `HttpUrl` states no length, so no CHECK holds one; the bound the contract does state, a declared canonical `href` of at most 8,192 UTF-8 bytes, is one (`v2_canonical_shape_ok`). A cap on every URL column needs the contract to state it first.
- A scoped seat (`client_scope_all = false`) with no `seat_sites` row sees no site; the contract requires at least one, which spans rows, so the route that scopes a seat enforces it. `client_scope_all` defaults to true (owner ruling): an invite that forgets it grants full scope, so the invite route always sets it. A default of false would refuse every sign-up, because 001's `handle_new_user` creates owner seats without naming the column.
- Hard-deleting one kept site fails while an account-wide alert rule last fired on one of its checks. Removing a site is a soft delete (`removed_at`), and deleting the account takes the rule too. Verify: `pnpm --filter @crawlmouse/web exec vitest run __tests__/v2-003-check-tables.test.ts -t "deleting"`.
- `reports.covers_check_ids` elements are not foreign keys; the writer checks they are the report's site's checks.
- Whoever writes `accounts.timezone` validates it against Postgres's zone names; the site effects fall back to UTC for a zone Postgres does not know.
- `apps/web/lib/billing/state-machine-apply.ts` still returns `siteEffects` for the caller to apply, and its comment says the RPC does not. After 003 the RPC applies them, and the staging changes `planStagingSites` plans; the caller must not apply either again (`planSites` given the database's kept schedule would plan a change). Update that file with the step that first calls it.
- `docs/deploy/spec51a-stage6-frontier-functions-runbook.md`'s routine check now returns `is_member`, `is_member_for_site` and `member_role`.
- **Re-applying 001 after 003 would put back 001's `apply_entitlement_transition`,** without the site effects. Do not re-run 001 once 003 is applied.

-- RedirectChain's shape: exactly hops and loop; at most 6 hops (MAX_REDIRECT_HOPS), each exactly
-- from (HttpUrl), status (an HTTP status 100-599) and location (HttpUrl or null). Which statuses a hop
-- may have, and the loop rule, are their own CHECKs.
create or replace function public.v2_redirect_shape_ok(p_redirect jsonb)
returns boolean language plpgsql immutable strict set search_path = pg_catalog
as $f$
declare
  v_hop jsonb;
begin
  -- One test per statement: SQL does not promise to evaluate OR left to right, and a cast must not
  -- run before its type is known.
  if jsonb_typeof(p_redirect) = 'null' then return true; end if;
  if jsonb_typeof(p_redirect) <> 'object' then return false; end if;
  if p_redirect - array['hops', 'loop'] <> '{}'::jsonb then return false; end if;
  if jsonb_typeof(p_redirect -> 'loop') is distinct from 'boolean' then return false; end if;
  if jsonb_typeof(p_redirect -> 'hops') is distinct from 'array' then return false; end if;
  if jsonb_array_length(p_redirect -> 'hops') > 6 then return false; end if;
  for v_hop in select e from jsonb_array_elements(p_redirect -> 'hops') e loop
    if jsonb_typeof(v_hop) <> 'object' then return false; end if;
    if not (v_hop ?& array['from', 'status', 'location']) then return false; end if;
    if v_hop - array['from', 'status', 'location'] <> '{}'::jsonb then return false; end if;
    if jsonb_typeof(v_hop -> 'from') <> 'string' then return false; end if;
    if not public.v2_http_url_ok(v_hop ->> 'from') then return false; end if;
    if jsonb_typeof(v_hop -> 'status') <> 'number' then return false; end if;
    if (v_hop ->> 'status')::numeric not between 100 and 599 then return false; end if;
    if (v_hop ->> 'status')::numeric <> trunc((v_hop ->> 'status')::numeric) then return false; end if;
    if not public.v2_nullable_url_ok(v_hop -> 'location') then return false; end if;
  end loop;
  return true;
end;
$f$;

returns boolean language sql immutable strict set search_path = pg_catalog
as $f$
  select case when jsonb_typeof(p_robots) = 'array'
              then not exists (
                select 1 from jsonb_array_elements(p_robots) r
                 where jsonb_typeof(r -> 'verdict') = 'string'
                   and r ->> 'verdict' not in ('allowed', 'disallowed_by_robots', 'not_measured'))
              else true end
$f$;

-- The robots_ua_unique rule: one entry per ua.
create or replace function public.v2_search_robots_ua_unique(p_robots jsonb)
returns boolean language sql immutable strict set search_path = pg_catalog
as $f$
  select case when jsonb_typeof(p_robots) = 'array'
              then (select count(r -> 'ua') = count(distinct r -> 'ua') from jsonb_array_elements(p_robots) r)
              else true end
$f$;

-- The contract's Header list: an array of at most 32 (MAX_HEADERS), each exactly name (crawled text,
-- 1 to 128 UTF-8 bytes) and value (crawled text, at most 1,024 UTF-8 bytes).
create or replace function public.v2_headers_shape_ok(p_headers jsonb)
returns boolean language plpgsql immutable strict set search_path = pg_catalog
as $f$
declare
  v_header jsonb;
begin
  -- One test per statement, as v2_redirect_shape_ok.
  if jsonb_typeof(p_headers) <> 'array' then return false; end if;
  if jsonb_array_length(p_headers) > 32 then return false; end if;
  for v_header in select e from jsonb_array_elements(p_headers) e loop
    if jsonb_typeof(v_header) <> 'object' then return false; end if;
    if v_header - array['name', 'value'] <> '{}'::jsonb then return false; end if;
    if not coalesce(public.v2_crawled_text_ok(v_header -> 'name', 128, 1), false) then return false; end if;
    if not coalesce(public.v2_crawled_text_ok(v_header -> 'value', 1024, 0), false) then return false; end if;
  end loop;
  return true;
end;
$f$;

-- Refuses UPDATE, DELETE and TRUNCATE whichever role writes (the service role included). Two writes are let through, both made by a
-- foreign-key action and checked here by what they leave behind: the delete of an event whose fix no
-- longer exists, and the clearing of by_seat_id once its seat no longer exists. SECURITY DEFINER, so
-- the cascade a user deletion starts can read site_fixes and seats whatever role started it.
create or replace function public.fix_events_append_only()
returns trigger
language plpgsql
security definer
set search_path = public, pg_catalog
as $$
begin
  if tg_op = 'DELETE' then
    if not exists (select 1 from public.site_fixes f where f.id = old.fix_id) then
      return old;
    end if;
  elsif tg_op = 'UPDATE' then
    if old.by_seat_id is not null and new.by_seat_id is null
       and (new.id, new.fix_id, new.at, new.kind, new.check_id)
           is not distinct from (old.id, old.fix_id, old.at, old.kind, old.check_id)
       and not exists (select 1 from public.seats s where s.id = old.by_seat_id) then
      return new;
    end if;
  end if;
  raise exception 'fix_events is append-only' using errcode = '55000';
end;
$$;

revoke all on function public.fix_events_append_only() from public, anon, authenticated, service_role;

-- An event's check is a check of its fix's site, and its seat a seat of that site's account.
create or replace function public.fix_events_references()
returns trigger
language plpgsql
security definer
set search_path = public, pg_catalog
as $$
begin
  if new.check_id is not null and not exists (
       select 1 from public.site_fixes f join public.checks c on c.site_id = f.site_id
        where f.id = new.fix_id and c.id = new.check_id) then
    raise exception 'fix_events: check_id must be a check of the fix''s site' using errcode = '23503';
  end if;
  if new.by_seat_id is not null and not exists (
       select 1 from public.site_fixes f join public.sites s on s.id = f.site_id
         join public.seats st on st.account_id = s.account_id
        where f.id = new.fix_id and st.id = new.by_seat_id) then
    raise exception 'fix_events: by_seat_id must be a seat of the fix''s account' using errcode = '23503';
  end if;
  return new;
end;
$$;

revoke all on function public.fix_events_references() from public, anon, authenticated, service_role;

-- Slack is a paid-plan channel (GATES in apps/web/lib/entitlement-v2.ts). A write that adds Slack to
-- a rule (an insert with it, an update that adds it or moves the rule to another account) is refused
-- when the account's effective tier is Free, as effectiveTier() there computes it: a no-card Pro trial
-- is Free from trial_ends_at, and past_due keeps past_due_tier for 168 hours from past_due_since. A
-- rule that already sends to Slack can still be updated after a downgrade, so it can be switched off
-- and alertFn can record when it fired; whether to send is alertFn's decision at send time. The
-- trigger runs AFTER the row's RLS check, so a client learns nothing about an account it cannot
-- write to, and it runs for every writer, the service role included.
create or replace function public.alert_rules_entitlement_check()
returns trigger
language plpgsql
security definer
set search_path = public, pg_catalog
as $$
declare
  v_tier text;
begin
  if 'slack' = any (new.channels)
     and (tg_op = 'INSERT' or not ('slack' = any (old.channels)) or new.account_id <> old.account_id) then
    select case
             when a.state = 'pro_trial' and a.trial_variant = 'no_card'
               then case when now() < a.trial_ends_at then a.tier else 'free' end
             when a.state = 'past_due'
               then case when now() < a.past_due_since + interval '168 hours' then a.past_due_tier else 'free' end
             else a.tier
           end
      into v_tier
      from public.accounts a
     where a.id = new.account_id;
    if v_tier is null or v_tier not in ('pro', 'agency') then
      raise exception 'alert_rules: Slack alerts need a paid plan' using errcode = '23514';
    end if;
  end if;
  return null;
end;
$$;

-- ─── Monthly partitions ───────────────────────────────────────────────────────────────────────────
-- A partition is a table of its own, and on production a new table in `public` would arrive with
-- every privilege for anon and authenticated (pg_default_acl). Partitions are therefore created in
-- the schema `partitions`, which no client role may use, each with RLS on and every role's
-- privileges revoked. A row is read and written through its parent, whose grants and policies apply.
--
-- v2_premake_month_partitions(from, through) creates each missing month from the month of `from` to
-- the month of `through` (inclusive, at most 37 months) for every table in `public` or `research` that is range-partitioned
-- on one date column named check_month or observed_month, found from the catalog, so a table
-- partitioned later is covered without editing this function. It returns how many it created. There
-- is no default partition: a row for a month that has no partition is refused, not misfiled. Postgres
-- clones a parent's row triggers onto a new partition but not its statement triggers, so each of the
-- parent's TRUNCATE triggers (the ledger's append-only rule) is created on the partition too. Run
-- daily by the owner's pg_cron job (docs/specs/v2/06b-data-foundations.md, runbook).

create schema if not exists partitions;
revoke all on schema partitions from public, anon, authenticated;

create or replace function public.v2_premake_month_partitions(p_from date, p_through date)
returns integer
language plpgsql
security definer
set search_path = pg_catalog
as $$
declare
  v_parent record;
  v_trigger record;
  v_first date;
  v_last date;
  v_month date;
  v_name text;
  v_role text;
  v_made integer := 0;
begin
  if p_from is null or p_through is null then
    raise exception 'partitions: from and through are required' using errcode = '22004';
  end if;
  v_first := date_trunc('month', p_from)::date;
  v_last := date_trunc('month', p_through)::date;
  if v_last < v_first or v_last >= v_first + interval '37 months' then
    raise exception 'partitions: % to % is not a range of at most 37 months', p_from, p_through
      using errcode = '22023';
  end if;
  for v_parent in
    select c.oid as parent_oid, n.nspname as schema_name, c.relname
      from pg_partitioned_table pt
      join pg_class c on c.oid = pt.partrelid
      join pg_namespace n on n.oid = c.relnamespace
      join pg_attribute a on a.attrelid = c.oid and a.attnum = pt.partattrs[0]
     where n.nspname in ('public', 'research')
       and pt.partstrat = 'r'
       and pt.partnatts = 1
       and a.attname in ('check_month', 'observed_month')
       and a.atttypid = 'date'::regtype
     order by 1, 2
  loop
    v_month := v_first;
    while v_month <= v_last loop
      v_name := format('%s_%s_%s', v_parent.schema_name, v_parent.relname, to_char(v_month, 'YYYY_MM'));
      if to_regclass(format('partitions.%I', v_name)) is null then
        execute format('create table partitions.%I partition of %I.%I for values from (%L) to (%L)',
                       v_name, v_parent.schema_name, v_parent.relname,
                       v_month, (v_month + interval '1 month')::date);
        execute format('alter table partitions.%I enable row level security', v_name);
        execute format('revoke all on table partitions.%I from public', v_name);
        for v_role in
          select rolname from pg_roles
           where rolname in ('anon', 'authenticated', 'service_role', 'crawl_worker', 'research_retention')
        loop
          execute format('revoke all on table partitions.%I from %I', v_name, v_role);
        end loop;
        for v_trigger in
          select t.tgname, t.tgfoid::regproc::text as fn
            from pg_trigger t
           where t.tgrelid = v_parent.parent_oid and not t.tgisinternal
             and (t.tgtype & 32) <> 0  -- TRUNCATE
        loop
          execute format('create trigger %I before truncate on partitions.%I for each statement execute function %s()',
                         v_trigger.tgname, v_name, v_trigger.fn);
        end loop;
        v_made := v_made + 1;
      end if;
      v_month := (v_month + interval '1 month')::date;
    end loop;
  end loop;
  return v_made;
end;
$$;

revoke all on function public.v2_premake_month_partitions(date, date) from public, anon, authenticated;
grant execute on function public.v2_premake_month_partitions(date, date) to service_role;

-- ─── apply_entitlement_transition: now with the site effects ──────────────────────────────────────
-- 001's body, unchanged up to the seat removal, then the site effects of CC-02's planSites
-- (apps/web/lib/billing/state-machine-sites.ts), decided as applied() decides them
-- (apps/web/lib/billing/state-machine.ts): pause_others on a move to Free from a paid tier;
-- otherwise pause_over_limit when the site limit falls, resume when it rises.
--
-- They apply to the account's primary sites (not staging, not removed), oldest first by created_at
-- to the millisecond (planSites compares Dates), then id; a site the user paused is not changed but
-- keeps its place in that order. A pause records paused_reason and keeps the schedule; a resume
-- clears it. On a move to Free the oldest site, unless the user paused it, takes Free's monthly
-- check, even if it was checked on deploy (Free has no deploy hooks:
-- GATES.free.stagingAndDeployHooks). Otherwise a timed schedule takes the tier's cadence (Free:
-- monthly, paid: weekly) and a site checked on deploy keeps that cadence, which planSites does not
-- model. A site given a timed cadence without a weekday or hour gets the weekday it was created on,
-- in the account's time zone (UTC if that zone is not one Postgres knows), at 06:00.
--
-- Staging sites (not removed) follow planStagingSites in the same file, on every transition: on a
-- tier without staging and deploy hooks (GATES[tier].stagingAndDeployHooks is false for Free alone)
-- a running staging site pauses as staging_not_in_plan, keeping its schedule; on a tier with them, one
-- paused as staging_not_in_plan runs again. A staging site paused for another reason is not changed.

create or replace function public.apply_entitlement_transition(
  p_account_id uuid,
  p_expected_version integer,
  p_state text,
  p_tier text,
  p_past_due_tier text,
  p_past_due_since timestamptz,

  p_trial_ends_at timestamptz,
  p_trial_used_at timestamptz,
  p_disputed_at timestamptz,

  p_site_limit integer,
  p_competitor_limit integer,
  p_at timestamptz,
  p_subscription_id text,
  p_changed_at timestamptz
)
returns integer

  v_history jsonb;
  v_since timestamptz;
  v_owner_seats integer;
  v_effect text;
  v_tz text;
begin
  if p_account_id is null or p_expected_version is null or p_state is null or p_tier is null
     or p_seat_limit is null or p_site_limit is null or p_competitor_limit is null or p_at is null then
    raise exception 'entitlement: a required argument is null' using errcode = '22004';
  end if;
  select * into v_account from public.accounts where id = p_account_id for update;
  if not found then
    raise exception 'entitlement: account % not found', p_account_id using errcode = 'P0002';
  end if;
  if v_account.entitlement_version <> p_expected_version then
    raise exception 'entitlement: account % is at version %, expected %',
      p_account_id, v_account.entitlement_version, p_expected_version using errcode = '40001';
  end if;

  v_history := v_account.state_history;
  if p_state <> v_account.state then
    -- The contract orders history strictly by time, compared in milliseconds. Entries are stamped
    -- to the millisecond, and one that would not come after the previous entry is recorded one
    -- millisecond after it.
    v_since := greatest(date_trunc('milliseconds', p_at),
                        (v_history -> -1 ->> 'since')::timestamptz + interval '1 millisecond');
    v_history := v_history || jsonb_build_array(jsonb_build_object(
      'state', p_state,
      'since', to_char(v_since at time zone 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.MS"Z"')));
    if jsonb_array_length(v_history) > 200 then
      -- Keep the first entry and the most recent 199.
      v_history := jsonb_build_array(v_history -> 0) || (
        select jsonb_agg(e order by i)
          from jsonb_array_elements(v_history) with ordinality as t (e, i)
         where i > jsonb_array_length(v_history) - 199);
    end if;
  end if;

  update public.accounts
     set state = p_state,
         tier = p_tier,
         past_due_tier = p_past_due_tier,
         past_due_since = p_past_due_since,
         trial_variant = p_trial_variant,
         trial_ends_at = p_trial_ends_at,
         trial_used_at = coalesce(trial_used_at, p_trial_used_at),
         disputed_at = coalesce(disputed_at, p_disputed_at),
         seat_limit = p_seat_limit,
         site_limit = p_site_limit,
         competitor_limit = p_competitor_limit,

         entitlement_changed_at = greatest(entitlement_changed_at, p_changed_at),
         state_history = v_history,
         entitlement_version = entitlement_version + 1,
         updated_at = now()
   where id = p_account_id;

  -- The newest active non-owner seats beyond the limit are removed. Invited seats are not counted:
  -- the invite step (a later CC) checks the limit when a seat is accepted.
  select count(*) into v_owner_seats
    from public.seats
   where account_id = p_account_id and status = 'active' and role = 'owner';
  update public.seats
     set status = 'removed', removed_at = p_at
   where id in (
     select id
       from public.seats
      where account_id = p_account_id and status = 'active' and role <> 'owner'
      order by accepted_at, created_at, id
     offset greatest(p_seat_limit - v_owner_seats, 0));

  elsif p_site_limit < v_account.site_limit then
    v_effect := 'pause_over_limit';
  elsif p_site_limit > v_account.site_limit then
    v_effect := 'resume';
  end if;

      select s.id, s.schedule_cadence, s.paused_reason,
             row_number() over (order by date_trunc('milliseconds', s.created_at), s.id) - 1 as place,
             extract(isodow from s.created_at at time zone v_tz)::smallint as created_weekday
        from public.sites s
       where s.account_id = p_account_id
         and s.staging_of_site_id is null
         and s.removed_at is null
    ), target as (
      select o.id, o.created_weekday,
             case
               when v_effect = 'pause_others' and o.place = 0 then 'monthly'
               when o.schedule_cadence = 'on_deploy' then 'on_deploy'
               when v_effect = 'resume' and o.place < p_site_limit
                 then case when p_tier = 'free' then 'monthly' else 'weekly' end
               else o.schedule_cadence
             end as cadence,
             case
               when v_effect = 'pause_others' then case when o.place = 0 then null else 'trial_ended' end
               when v_effect = 'pause_over_limit' and o.place >= p_site_limit
                    and o.paused_reason is null and o.schedule_cadence is not null then 'over_limit'
               when v_effect = 'resume' and o.place < p_site_limit then null
               else o.paused_reason
             end as reason
        from ordered o
       where o.paused_reason is distinct from 'user'
    )
    update public.sites s
       set schedule_cadence = t.cadence,
           schedule_iso_weekday = case when t.cadence in ('weekly', 'monthly')
                                       then coalesce(s.schedule_iso_weekday, t.created_weekday)
                                       else s.schedule_iso_weekday end,
           schedule_hour_local = case when t.cadence in ('weekly', 'monthly')
                                      then coalesce(s.schedule_hour_local, 6)
                                      else s.schedule_hour_local end,
           paused_reason = t.reason,
           updated_at = now()
      from target t
     where s.id = t.id
       and (s.schedule_cadence is distinct from t.cadence or s.paused_reason is distinct from t.reason);
  end if;

  update public.sites s
     set paused_reason = case when p_tier = 'free' then 'staging_not_in_plan' end,
         updated_at = now()
   where s.account_id = p_account_id
     and s.staging_of_site_id is not null
     and s.removed_at is null
     and s.paused_reason is not distinct from
         case when p_tier = 'free' then null else 'staging_not_in_plan' end;

  return v_account.entitlement_version + 1;
end;
$$;

language plpgsql
